## Ambiguities / decisions worth a second look in review

- **In-flight push vehicle.** §6.3/§6.13/§6.14 want a push that *began*
  before the swap and *commits* after it. There is no edge route for
  `/_do/push/commit`, so a real `git-receive-pack` cannot be parked mid-push
  deterministically. The tests use the staged-import machinery
  (`import_stage`/`import_begin`/`import_until_commit_phase`) — the same
  `pushes`-row vehicle the C1 tests use — whose `gc_epoch` is pinned at
  stage time and whose commit is stepped explicitly. For the lossy arms the
  spec's "gc ran during push" is exercised as the import's re-check finding
  a swept link missing → `push_state == "rejected"` (deterministic; the
  exact rejection string is not pinned).
- **`pause_drain` needs drain work.** The swap check runs at the top of the
  drain loop; with an empty frontier+pending the slice swaps before the
  drain iterates, so `gc.drain.after_read` never fires. Tests that pause
  the drain therefore push once *before* arming the pause — that is also
  what makes the paused-drain pushes land mid-drain.
- **`gc.swap.fallback.after_deadmark` placement.** The spec names it inside
  the fallback's *retire* span (steps 7–8); whether the 6a wipe path also
  fires it is unspecified. `test_crash_points::swap-fb-deadmark` uses an
  all-reachable cohort to force the retire branch so the point is hit.
- **`run_at <= now` oracle.** There is no server clock in the jobs view, so
  §6.16 is asserted as ordering: released `gc_compact.run_at <=
  gc_mark.run_at` (with quiet=0 the mark is pushed to `now+max(quiet,1)`,
  i.e. strictly behind — `assertLessEqual` tolerates equal stamps).
- **`swap["tries"]`/`slices`/`retired_bytes`/`kept` are not asserted** —
  only the spec-named fields `retired`, `lossy`, `fallback` are, to keep
  phase A red without over-pinning the JSON.
- **§6.16 "compact chain runs between two GC chains"** is covered lightly:
  after release, stepping `gc_compact` must run (`s["ran"]`) — a full
  two-chain interleaving soak is §6.10, out of scope here.
- The `total==0` fixture reuses `test_keep_total0_handoff_order`'s recipe
  (garbage pack strictly older than candidates, `head` re-pointed before
  the delete, `time.sleep(1.1)` for strict `created_at` ordering — the one
  sanctioned non-poll sleep, copied verbatim).
- `marked` flag wipes at chain end, so every cohort assertion captures
  `cohort_ids` at `presweep`, not after the drain.

## Phase A setup fix

Three cases never reached the intended missing-swap contract — their SETUP
stalled before the red assertion. Setup-only changes in
`tests/harness/test_swap.py` (no production swap/drain code, no softened
assertions):

- **`test_crash_points` arm `cons-part`** — `gc.consolidate.after_part` sits
  past the first uploaded MPU part, so a single-part seed reported "done"
  without the site ever existing. The arm now uses the `consolidate_parts`
  recipe from `test_harness._failpoint_case`: `gc_part_bytes` at the dev-R2
  non-final-part floor (5 MiB) plus ~6 MiB of incompressible binary committed
  before the seed pushes so it lands inside a candidate pack — the build
  spans >=2 parts. Expected result now: the failpoint fires
  (`outcome == "crashed"`) and the arm passes — it pins unchanged
  consolidate crash/recovery behaviour.
- **`test_stable_large_drain_never_falls_back` (§6.5)** — the uncapped
  `ge.step(gc_mark)` init could finish the whole mark before the
  pre-baseline pushes; those pushes then queued a mark that the phase=build
  M4 guard only Reschedules, so `step_until` never reached "done". The
  writes now land inside a parked mark window (`tb.pause_mark` → pushes →
  `tb.release_pause`, the `test_mark_completes_under_writer` pattern), then
  the chain is driven by the new `mark_to_build` helper: it steps gc_mark
  until `gc.phase == "build"` publishes — keyed on the persisted phase, not
  a row's outcome, because pushes staked under a parked mark leave a queued
  gc_mark row behind (`enqueue` dedups vs 'queued' only) that a
  `step_until(.., "done")` could spin on at the M4 guard. Expected red
  unchanged: `ge.last_swap` is None at `assertIsNotNone(swap)`.
- **`test_try_baseline_after_presweep_writes` (§6.17), both arms** — same
  stall class fixed the same way: `pause_mark`/`release_pause` around the
  `pre` push, then `mark_to_build`. The delete arm's `pre2` push also moved
  inside the mark window — a post-baseline push would charge the try before
  `gc.drain.after_read` could ever park the slice, so the drain work must
  be pre-baseline. Expected red: `quiesce` fails on `assertIsNotNone(swap)`
  (no `gc_last_swap`); `delete_during_drain` reaches `pause_drain` and times
  out on the missing `gc.drain.after_read` host site.

Not committed — the parent process commits.
